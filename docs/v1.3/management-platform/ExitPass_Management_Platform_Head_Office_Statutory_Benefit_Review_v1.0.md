# ExitPass Management Platform Head Office Statutory Benefit Review v1.0

## Status

`IMPLEMENTED_AND_ACCEPTED` for the bounded feature-pinned backend and frontend slice.

## Purpose

The Management Platform provides an explicitly permissioned Head Office workspace for reviewing statutory-benefit requests submitted to Central PMS by WebPay and the Assisted Payment Terminal (APT). Central PMS remains the sole request, evidence, workflow, decision, payable-basis, and audit authority.

There is no browser connection to WebPay, APT, Operator Console, payment providers, or a client-owned database. WebPay and APT submit to Central PMS through their existing service channels. The Management Platform reads and decides through Central PMS only. Client applications do not call or message each other.

## Canonical Sources

| Purpose | Source | Authority |
| --- | --- | --- |
| Service-channel review linkage | `operator_console.statutory_discount_service_channel_reviews` | Central PMS safe review read model |
| Terminal decision | `discounts.statutory_discount_decision_commands` | Central PMS canonical workflow |

No duplicate request, queue, decision, or evidence-retention table is introduced.

## API

Contract: `contracts/management-platform/statutory-benefit-review-api.v1.json`

Routes:

- `GET /v1/management-platform/statutory-benefit-requests`
- `GET /v1/management-platform/statutory-benefit-requests/{decisionCommandReference}`
- `GET /v1/management-platform/statutory-benefit-requests/{decisionCommandReference}/evidence`
- `POST /v1/management-platform/statutory-benefit-requests/{decisionCommandReference}/decision`

The list is server paginated and defaults to pending requests. Controlled filters cover status, authorized Site, source channel, benefit type, half-open submission period, and exact safe request, parking-session, or ticket reference.

## Authorization

The module reuses the existing permissions:

- `statutory-discounts.review.queue.read`
- `statutory-discounts.review.detail.read`
- `statutory-discounts.evidence.review.view`
- `statutory-discounts.decision.approve`
- `statutory-discounts.decision.reject`

These permissions are not implied by administrator status. A Head Office user receives enterprise-wide visibility only when an authorized role assignment carrying the relevant permission also has an explicit active `GLOBAL` scope grant. Site and Site Group grants remain bounded. H-006 session status, expiry, credential version, authorization epoch, account status, role assignment, permission binding, and scope grants are resolved by Central PMS. Client-authored authority headers are not accepted.

The canonical local/UAT role bundle is `HEAD_OFFICE_STATUTORY_BENEFIT_REVIEWER`. It contains only the five permissions above and intentionally excludes User Administration, fiscal mutation, payment mutation, gate control, and configuration authority. Production assignment remains a governed identity-administration action.

## Decision Integrity

The Management facade delegates to the existing canonical staged statutory decision services. Approval and rejection are terminal. Same-decision replay is idempotent; a conflicting terminal decision returns controlled `409`. The request carries an optimistic version and idempotency key. Reviewer identity comes from the authenticated session, decision time is generated by Central PMS, and rejection requires a reason. Approval continues through the existing Central PMS-only validation and payable-basis path.

## Privacy And PHP Boundary

The browser receives no plate number, raw evidence, object key, storage locator, checksum, token, credential, or private authority mapping. Evidence metadata has a separate permission and audit event. The UI stores no request, evidence, decision, or authority data in browser persistence and clears protected state with the authenticated shell.

ExitPass supports PHP only. Monetary facts are returned only when the canonical currency is exactly `PHP`; other or missing currency is rejected rather than displayed. The UI uses peso presentation and provides no currency selector, conversion, grouping, or multi-currency behavior.
